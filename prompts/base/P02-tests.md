# P02. Тесты до реализации

По плану P01 напиши тесты по каждому критерию приёмки истории {ID}. Правила:

- test/unit/ для доменной логики (без HTTP), test/api/ для эндпоинтов (временная БД через DB_PATH в tmp).
- Каждый критерий — хотя бы один тест; негативные сценарии обязательны (403/409/400 по каталогу ошибок).
- Тесты должны падать (существующей реализации нет/не хватает).
- Запусти `npm test`, приложи вывод: какие падают и почему.

Не реализовывай функциональность на этом шаге.
