## [0.5.0] — 2026-10-30

Ветка `v0.5.0`, автор ayurasov.

### Добавлено

- **Кластер процессов** (`main.ts`, `infra/concurrency.ts`): `WEB_CONCURRENCY` (`auto` — по ядрам), перезапуск упавших процессов, останов при частых падениях; пул соединений на процесс min(10, 40 / процессов), `DB_POOL_SIZE`.
- **Кэш графика**: таблица `data_version` (16 строк, отложенные триггеры на таблицах графика — при фиксации, один раз за транзакцию), `ScheduleService` на простом SQL, кэш ответов в памяти по версии, `ETag` и `304 Not Modified`.
- **Поток событий** (`server/src/events`): `POST /events/ticket`, `GET /events` (SSE: `hello`, `notifications`, `data`, heartbeat); клиент `subscribeLive` с откатом на опрос; nginx без буферизации, `worker_connections 16384`.
- **Метрики** (`infra/metrics.ts`, `GET /metrics`): HTTP по шаблонам маршрутов, цикл событий, процессор и память, SSE, соединения БД, очередь писем, фоновые задачи, реплики и архив WAL; сложение процессов кластера по IPC; `METRICS_TOKEN`. `deploy/monitoring`: Prometheus (профиль `monitoring`), 15 правил оповещений, панель Grafana.
- **Реплика и архив WAL** (`docker-compose.replica.yml`, `deploy/postgres`): горячий резерв по слоту, архив WAL (`archive_timeout` 300 с), ежедневные физические копии с очисткой архива; `DB_HOST` для переключения.
- **Нагрузка**: `prisma/load-seed.ts` (`npm run db:seed:load`, 5000 сотрудников), генератор `tools/load/run.mjs` (режимы опроса и `--sse`); отчёт `docs/progress/load-v0.5.0.md`.
- Код ошибки `service-unavailable` (503, `Retry-After: 5`) для P2024, P2028, P1001, P1002, P1017; счётчик `vp_db_errors_total`.
- CI: задание «Реплика PostgreSQL, архив WAL и переключение»; дымовой прогон проверяет `/metrics` и поток событий через nginx.
- ADR-012, ADR-013, ADR-014.
- По итогам аудита интерфейса (`docs/progress/audit-v0.5.0.md`): `GET /employees?manager=` — прямые подчинённые; `POST /notifications/read-all`; `employeeDept` в заявках; `managerName` в отделах и проектах; событие `revoked` в потоке событий; директива `v-dialog` для модальных окон; токены заливок `--color-*-fill` под белым текстом.
- Тесты: passwords.unit, schedule.e2e, events.e2e, metrics.e2e, concurrency.unit, audit-fixes.e2e; лимит входа на двух экземплярах; virtualWindow, absentPerDay; e2e интерфейса «диалог заявки» и «сброс пароля закрывает открытую вкладку».

### Изменено

- Хеширование паролей — асинхронный scrypt в пуле потоков; для неизвестного логина проверяется подставной хеш.
- Лимит входа — в PostgreSQL (`login_attempts`, нежурналируемая), скользящая оценка по двум минутным окнам.
- График отпусков в браузере — виртуальный список; нагрузка по дням — разностный массив.
- Выгрузка XLSX — потоковая запись (`WorkbookWriter`) с уступкой процессора каждые 100 строк.
- nginx — шаблон конфигурации (`NGINX_RESOLVER`, `API_UPSTREAM`), адрес `server` разрешается каждые 10 с.
- Контраст текста и заливок — не ниже 4,5:1 в обеих темах (WCAG 2.1 AA): затемнены `--color-text-soft`, `--color-text-muted`, `--color-primary`, `--color-success`, `--color-danger` и метки светлой темы, осветлён `--color-text-soft` тёмной; кнопки, полосы графика и счётчики — на заливках.
- Узкие экраны: вкладки и фильтры без обрезки, показатели графика 2 × 2, колонка имён графика 156 px, подпись полосы видна при прокрутке; на сенсорных экранах цели нажатия 36–40 px.
- Норма и перенос дней в карточке сотрудника и в API — до сотых (как в импорте).
- Приложение при загрузке сначала обновляет токен, затем читает профиль (без заведомого `401`).

### Исправлено

- Взаимная блокировка (`40P01`) при одновременной подаче заявок сотрудником и его руководителем под нагрузкой: блокировки `FOR NO KEY UPDATE`, счётчик версии — при фиксации (миграция `data_version_on_commit`).
- Смена пароля и увольнение не отзывали выданные access-токены (проверка `pw_version` и активности теперь в `JwtAuthGuard`, кэш 10 с).
- Фильтр ошибок превращал любой `401` в `auth/invalid-credentials`.
- `429 rate-limited` не нёс заголовок `Retry-After`.
- После пересоздания контейнера `server` nginx отвечал `502`.
- Команда создания первого администратора в руководстве по развёртыванию печатала `Promise` вместо хеша.
- Дубли строк в журнале зависимостей `docs/decisions.md`.
- Аудит интерфейса: отклонённое обновление токена оставляло вкладку «вошедшей»; вход отвечал «неверный пароль» на перегрузку и обрыв сети; кэш сеанса сбрасывался до фиксации транзакции; отзыв сеанса не закрывал поток событий; руководитель не видел подчинённых вне первых 200 сотрудников, очередь согласования — только первые 200 заявок; «Справочники» загружали всех сотрудников ради имён руководителей; «График работы» и очередь согласования загружали график всей организации; предпросмотр заявки через Новый год считал январские праздники днями отпуска; модальные окна без имени, удержания фокуса и Esc; щелчок по уведомлению не вёл в раздел; руководитель из другого отдела пропадал из карточки; сбой сети кэшировался как «нет праздников».

### Исправлено

- Аудит сброса пароля; 413 и P2002 — коды каталога вместо 500; схема `Employee` в контракте.

### Добавлено

- **Клиент**: новый интерфейс (токены, иконки `AppIcon`, темы), экраны «Команда» и «График работы», подбор дат в форме заявки, полоса нагрузки и сравнение на графике, график месячной нагрузки.
- **Тесты**: `balance.unit`, `coverage.unit`, `analytics.e2e`, `concurrency.e2e`, `contract.e2e`; модульные тесты `web/src/lib`; Playwright `web/e2e` и задание e2e в обоих CI.
- **Поставка**: сервис `backup` (`pg_dump -Fc`, атомарная запись, срок хранения); CSP в nginx и `vite preview`; собранный seed и Prisma CLI в образе сервера.
- **Документация**: конвейер `tools/docs` (pandoc → PDF/DOCX, рендер схем, генерация таблиц), 17 схем, снимки экранов, руководства пользователя, администратора и по развёртыванию; спецификации 00–11 переписаны.

### Изменено

- Баланс: праздники не входят в дни отпуска (ТК РФ, ст. 120); лимит — по доступному остатку за вычетом заявок на согласовании; остаток округляется до сотых.
- Лимит входа: 10/мин на пару «адрес + логин», 60/мин на адрес; доверенные прокси — `TRUST_PROXY`.
- Выгрузка XLSX: область по правам; колонка «Дней отпуска» без праздников.
- Seed идемпотентен; демо-заявки на согласовании отключаются `SEED_DEMO=0`.
- Контракт OpenAPI приведён к реализации (34 пути).

### Исправлено

- Гонки: `SELECT … FOR UPDATE` строки сотрудника при создании и изменении заявки, строки заявки при решении; повторное решение — 409 `stale-state`.
- После согласованного переноса очищаются `changeFrom*`; отклонённый перенос возвращает прежние даты.
- Администратор видит все заявки в очереди согласования.
- Клиент обновляет токен одним запросом на все параллельные вызовы.
- Дымовая проба CI не падает на обрыве соединения до готовности API.

## [0.1.0] — 2026-10-27

Полная замена прототипа зрелой платформой. Ветка `v0.1.0`, автор ayurasov (исполнение — ИИ-ассистент ZCode/GLM).

### Добавлено

- **Сервер** (`server/`): NestJS 11 + TypeScript strict + Prisma 6 + PostgreSQL 17. Аутентификация (scrypt, JWT access 15 мин, refresh с ротацией в httpOnly-cookie, pw-версия пароля), глобальные guards с `@Public`, заявки с конечным автоматом (перенос `changeFrom`, удаление `pendingDeletion`, авто-approve за подчинённого), пересечения 409, жёсткий лимит баланса (политика в настройках), ТК РФ 14 дней, график интервалами с конфликтами отделов, производственный календарь 2026–2027, справочники (отделы/проекты/группы), настройки организации, append-only аудит в одной транзакции с изменениями, уведомления, `/healthz`+`/readyz`, Swagger на `/api/docs`. Ошибки — RFC 9457 по каталогу документов 2.
- **Клиент** (`web/`): Vue 3 + Vite + TypeScript + Pinia + vue-router, без компонентных библиотек. Дизайн-система по внутренним референсам (токены todo-planner, тёмная тема puls/gantt): экраны входа, графика-гант (фильтры, легенда, конфликты), «Мой отпуск» (KPI, заявка, уведомления, ТК-предупреждение), согласования (одобрение/отклонение с причиной), сотрудники (CRUD, одноразовый пароль, пагинация, поиск), справочники, настройки (порог конфликта, политика лимита, смена пароля), аудит. Light/dark, адаптив до мобильных.
- **Поставка**: `docker-compose.yml` (postgres 17 / server / web за nginx), multi-stage Dockerfile'ы, миграции Prisma при старте, `Makefile`.
- **Миграция данных прототипа**: `server/prisma/seed.ts` — 131 сотрудник (id и логины сохранены, пароли в scrypt), 14 отделов, 268 заявок, недельные шаблоны режимов.
- **SBOM и лицензии**: CycloneDX 1.5 на оба пакета (`make sbom`), автогенерируемый отчёт `docs/sbom/licenses-report.md` с классификацией для реестра ОП (691 компонент, все лицензии разрешительные); документ 11.
- **Тесты**: 19 e2e (vitest + supertest + unplugin-swc; сервер на тестовой БД vacation_test) — аутентификация, ротация refresh, RBAC, жизненный цикл заявок, лимиты, аудит; дымовой скрипт 17 проверок.
- **Документация**: комплект 00–11 (архитектура 2.0 под зрелый стек), PDF-версии в `docs/pdf/`, история версий и авторство `docs/versions.md`.

### Удалено

- Прототип: `server.js`, `public/index.html`, snapshot-протокол `PUT /api/state`, `install.bat`/`start.bat`, README-Windows (git-история сохраняет всё).

### Безопасность

- Пароли только scrypt-хеши; пароли/токены отсутствуют в журналах, ответах и выгрузках; единая 401-ошибка входа без раскрытия причины; повторное использование refresh-токена отклоняется ротацией.
