# ADR-005. Доменный слой без HTTP-зависимостей

Дата: 27.10.2026 · Статус: принято · Решение Р6 документа 1 · Актуализировано 29.10.2026 (1.0.0): после перехода на NestJS (ADR-009) правила переложены на модули NestJS, первоначальная схема `src/domain/` + `src/api/` на Express не реализовывалась

## Контекст

В прототипе вся бизнес-логика (статусы, права, балансы) — в браузере и в обработчиках `server.js`. Для переноса на сервер нужен слой, тестируемый без HTTP, который ИИ-ассистенты смогут проверять автотестами.

## Решение

Первоначально (27.10.2026): `src/domain/<модуль>/` — чистые функции и сервисы без Express, `src/api/` — тонкие роуты с валидацией ajv.

Реализовано на NestJS (с v0.1.0, ADR-009):

- **Доменная логика** — в сервисах модулей (`server/src/<домен>/*.service.ts`) и в чистых функциях без зависимостей от NestJS и БД: расчёт дней и остатков (`requests/balance.ts`), покрытие и рабочий календарь (`analytics/coverage.ts`), область согласования (`requests/approval-scope.ts`).
- **Контроллеры тонкие:** DTO с class-validator (глобальный `ValidationPipe`), проверка прав, вызов сервиса. Сервисы не получают `req`/`res` и не импортируют `express`.
- **Ошибки** — `ProblemException` с кодом из каталога (`infra/problems.ts`, документ 2); глобальный `ProblemFilter` превращает их в `application/problem+json`.

## Последствия

+ Таблица состояний заявок и расчёты остатков проверяются модульными тестами без HTTP и БД (`balance.unit.test.ts`, `coverage.unit.test.ts`) — быстро и наглядно.
+ Правила в одном месте; интерфейс и будущие клиенты получают одинаковую семантику.
− Сервисы работают с Prisma напрямую, а не через интерфейсы репозиториев: транзакции, блокировки строк и ограничения PostgreSQL — часть поведения, поэтому сервисы проверяются e2e-тестами на тестовой БД `vacation_test`, а не на in-memory реализациях.
− Больше файлов и косвенности, чем «писать в роуте»; для 2–3 разработчиков — приемлемая цена.

## Правила

1. Сервисы и чистые функции не импортируют `express` и `node:http`; «сегодня» в часовом поясе организации — `infra/clock.ts`.
2. Ошибки — `ProblemException` с кодом из каталога; новый код добавляется в каталог документа 2 и `infra/problems.ts` одновременно.
3. Расчёты без обращения к данным — чистые функции с модульными тестами; операции с данными — методы сервиса, изменение и журнал изменений в одной транзакции (ADR-006).
