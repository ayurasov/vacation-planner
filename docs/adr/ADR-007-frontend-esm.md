# ADR-007. Поэтапный перенос фронтенда на ES-модули без сборки

Дата: 27.10.2026 · Статус: принято · Решение Р8 документа 1

## Контекст

`public/index.html` — 4,6 тыс. строк рабочего кода (график, заявки, справочники, аналитика). Переписывание на SPA-фреймворк — недели работы и регрессия по всем фичам ради архитектурной чистоты; команда малая.

## Решение

Фронтенд остаётся на ванильном JS. На этапе 1 код выносится в ES-модули `public/src/` (api-client, state, screens/, components/) и переводится на API v1. Без бандлера: браузеры цели ES-2020+ поддерживают нативно. HTML-точка входа остаётся тонкой.

## Последствия

+ Сохранение работающей логики; малые шаги (экран → модуль); нет инфраструктуры сборки и её уязвимостей.
+ Нативные ES-модули отлично дебажатся.
− Нет минификации/полифиллов — для внутренней сети приемлемо (объём модулей < 300 КБ).
− Дисциплина зависимостей вручную; ESLint подключается к фронтенду на этапе 1 (правило no-restricted-syntax для innerHTML с данными — этап 2).

## Критерии пересмотра

Появление общего компонентного дизайна (дизайн-система), TypeScript-требований или публичного мобильного веба — рассмотреть Vite + фреймворк, сохраняя API-клиент.
