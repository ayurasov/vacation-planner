# ADR-002. Гранулярный REST API v1 вместо снимка состояния

Дата: 27.10.2026 · Статус: принято · Решение Р3 документа 1

## Контекст

Протокол этапа 0: клиент после любого изменения отправляет `PUT /api/state` со всеми данными организации (274 КБ на 131 сотрудника, ~1 МБ на 500). Последняя запись перезаписывает все остальные; сервер не может проверить права — он видит только снимок; любые интеграции невозможны.

## Решение

Целевой протокол — гранулярный REST `/api/v1` по `contracts/openapi-vacation-api-v1.yaml`. Одна операция пользователя = один HTTP-вызов = одна транзакция. Снимок удаляется после миграции (E10-02).

## Последствия

+ Конкурентность без потерь; серверные права и валидация; аудит возможен; открыта дверь для интеграций и мобильного клиента.
− Выше стоимость разработки: 39 операций вместо 3; требуется версионирование контракта.
− Переходный период: до E10-02 живут оба протокола (двойной surface атаки — компенсируем правами администратора на state-эндпоинты с этапа 1-й недели).

## Критерии пересмотра

Появление offline-клиента (очередь операций на клиенте) — потребуется протокол синхронизации поверх операций, но v1 сохраняется.
