# О документе

Инструкция описывает, как эксперту получить доступ к программе «Планировщик отпусков» версии 1.0.0 и проверить заявленные функциональные характеристики. Предусмотрены два способа: работа на демонстрационном стенде правообладателя и самостоятельная установка из дистрибутива. Порядок проверки привязан к идентификаторам функций из «Описания функциональных характеристик» (`Ф-XX.YY`); в конце приведены проверки технологической независимости и форма для записи результатов.

Значения, которые правообладатель указывает при подаче заявления, отмечены `[заполняет правообладатель]`.

# Способ 2. Установка из дистрибутива

Для проверки на оборудовании эксперта нужен сервер или виртуальная машина с 64-битным Linux (x86-64), Docker Engine 24+ и Docker Compose v2.

<!-- sizing -->
Рекомендуемые процессор, память и диск для проверочного стенда определяются по результатам нагрузочных измерений версии 1.0.0 и будут указаны здесь и в «Руководстве по развёртыванию».

1. Проверьте контрольную сумму и распакуйте дистрибутив, перейдите в каталог с файлом `docker-compose.yml`:

   ```bash
   sha256sum -c SHA256SUMS
   ```

   Состав дистрибутива и контрольные суммы: `[заполняет правообладатель: архив исходных текстов, архивы образов, файл SHA256SUMS]`.

2. Создайте рядом с `docker-compose.yml` файл `.env`:

   | Переменная | Значение для проверки |
   | --- | --- |
   | `JWT_SECRET` | Обязательно: случайная строка не короче 32 символов (`openssl rand -base64 48`) |
   | `APP_URL` | Адрес, по которому эксперт откроет стенд, например `https://vp.example.local` |
   | `BACKUP_INTERVAL`, `BACKUP_KEEP_DAYS` | Можно не задавать: копия раз в сутки, хранение 14 дней |

   Почта (`SMTP_*`) и единый вход (`OIDC_*`) необязательны и нужны только для проверок 7 и 43 — «Руководство по развёртыванию», разделы «Почта» и «Единый вход».

3. Запустите стенд:

   ```bash
   docker compose --profile full up -d --build
   docker compose --profile full ps
   ```

   Если дистрибутив содержит готовые образы, перед запуском загрузите каждый архив командой `docker load -i <архив образа>` и запустите стенд по описанию в составе дистрибутива; иначе образы собираются из исходных текстов — для сборки нужен доступ к реестрам пакетов npm и образов Docker или к их зеркалам в организации. При первом старте сервер применяет миграции базы данных. Стенд отвечает на порту 80.

4. Загрузите демонстрационные данные:

   ```bash
   docker compose exec server npm run db:seed:prod
   ```

   В конце вывода — «Seed завершён: сотрудников 131, отделов 14, …».

5. Откройте стенд в браузере. Cookie сеанса выдаётся с признаком `Secure`, поэтому стенд открывают по HTTPS через обратный прокси организации либо по адресу `http://localhost` — на самом сервере или через туннель `ssh -L 8080:localhost:80 <пользователь>@<сервер>` с адресом `http://localhost:8080`. По обычному HTTP с другого адреса вход выполняется, но сеанс не сохраняется при обновлении страницы.

6. Войдите под учётными записями из таблицы выше; пароли демонстрационных данных: `[заполняет правообладатель]`.

Подробные требования, настройка HTTPS, почты, единого входа и мониторинга — в «Руководстве по развёртыванию».

# Порядок проверки функций

Каждая строка — короткая проверка: под какой учётной записью, что сделать, что должно получиться. Проверки удобно выполнять сверху вниз: некоторые продолжают предыдущие (например, заявка из проверки 13 согласуется в проверке 17). Для проверок с двумя учётными записями используйте два разных браузера или обычное и приватное окно. Даты новых заявок выбирайте так, чтобы они не пересекались с другими отпусками того же сотрудника. Проверка 27 отложенная — её результат виден через сутки; проверку 33 выполняйте последней в своём разделе: утверждение графика необратимо. Проверки 7 и 43 необязательные — они требуют провайдера единого входа и почтового сервера.
