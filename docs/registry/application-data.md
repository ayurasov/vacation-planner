# О документе

Документ собирает в одном месте сведения, которые вносятся в заявление о включении программы «Планировщик отпусков» в единый реестр российских программ для ЭВМ и баз данных (Правила формирования и ведения реестра утверждены постановлением Правительства РФ от 16.11.2015 № 1236). Здесь же — проекты деклараций о соответствии требованиям и порядок подтверждения совместимости с российскими операционными системами.

Перед подачей проверьте формулировки по действующей редакции Правил и по форме заявления в личном кабинете правообладателя: требования к реестру регулярно уточняются. Поля, которые заполняет только правообладатель, отмечены `[заполняет правообладатель]`. Технические сведения взяты из исходных текстов версии 1.0.0 (ветка `v1.0.0`), технического задания (`docs/specs/08-tz.md`), описания архитектуры (`docs/specs/01-architecture.md`) и руководства по развёртыванию.

## Отсутствие принудительного обновления и управления из-за рубежа

Сведения о программе не составляют государственную тайну. Программа:

- не содержит механизмов принудительного или автоматического обновления: новая версия устанавливается только действиями администратора заказчика (получение версии и пересборка стенда `docker compose --profile full up -d --build`); миграции базы данных применяются при старте уже установленной версии;
- не содержит механизмов управления из-за рубежа и не принимает команд из внешних источников: сервер обрабатывает только запросы пользователей, прошедших аутентификацию, к собственному API (`/api/v1`) и служебные пробы `/healthz`, `/readyz`, `/metrics` внутри сети стенда;
- не передаёт данные правообладателю или третьим лицам: в коде программы нет телеметрии, проверки лицензий через интернет и обращений к облачным сервисам; веб-интерфейс загружает ресурсы только со своего адреса (политика CSP `default-src 'self'`), без внешних CDN, шрифтов и счётчиков;
- устанавливает исходящие соединения только с серверами организации, адреса которых задаёт администратор: почтовый релей (`SMTP_HOST`) и провайдер единого входа OpenID Connect (`OIDC_ISSUER`: документ discovery, ключи JWKS, обмен кода на токен). Без настройки эти соединения не устанавливаются;
- работает в изолированной сети без доступа к интернету: интернет нужен только при сборке образов из исходных текстов (загрузка базовых образов и пакетов npm); для закрытых контуров поставляются готовые образы.

> **Условие подписания декларации.** Сторонние инструменты в составе поставки могут обращаться в интернет, если он доступен. Проверка версии командной строки Prisma (`checkpoint.prisma.io`) в образе `server` отключена (`CHECKPOINT_DISABLE=1`), но npm при запуске `npx prisma migrate deploy` на старте контейнера проверяет новую версию npm в `registry.npmjs.org`, а пакет `@scarf/scarf` (зависимость `swagger-ui-dist`) при `npm ci` во время сборки отправляет событие установки на `scarf.sh`. В закрытом контуре эти запросы безуспешны и на работу не влияют. До подписания декларации их нужно отключить (`NPM_CONFIG_UPDATE_NOTIFIER=false`; `SCARF_ANALYTICS=false` или `scarfSettings.enabled: false`) и подтвердить отсутствие исходящих соединений проверкой из «Инструкции для эксперта» — см. «Комплект документов», раздел «Наблюдения».

## Свободное программное обеспечение в составе

Программа использует компоненты свободного программного обеспечения на условиях их лицензий. Перечень компонентов с версиями и лицензиями — в SBOM (`sbom/server.cdx.json`, `sbom/web.cdx.json`, формат CycloneDX 1.5; формируются в CI на каждый коммит), в перечне `docs/sbom/sbom-components.csv`, в отчёте «SBOM и анализ лицензий» (`docs/sbom/licenses-report.md`); тексты уведомлений — в документе «Сторонние компоненты и лицензии». Сторонние библиотеки, входящие в поставку, распространяются по разрешительным лицензиям (MIT, ISC, Apache-2.0, BSD и др.); компонентов с сильным копилефтом (GPL, AGPL) и слабым копилефтом (LGPL, MPL) среди них нет, библиотека с двойной лицензией `MIT OR GPL-3.0-or-later` (jszip) используется на условиях MIT. Лицензии GPL встречаются только у программ базовых образов контейнеров (Alpine Linux: BusyBox и др.), которые поставляются вместе с программой как отдельные программы (агрегирование) и не связываются с её кодом. Политика лицензий проверяется в CI: компонент с копилефтной или неопределённой лицензией блокирует слияние (`docs/specs/11-sbom-licenses.md`).

# Совместимость с российскими операционными системами

## Требование

Правилами формирования реестра предусматривается подтверждение совместимости программы с операционными системами, включёнными в реестр (требование вводится поэтапно; проверьте действующую редакцию Правил и количество ОС, с которыми требуется совместимость, на дату подачи).

## Техническая основа совместимости

| Часть программы | Как работает на российских ОС |
| --- | --- |
| Серверная часть | Контейнеры Docker на любом 64-битном Linux (x86-64) с Docker Engine 24+ и Docker Compose v2. Образы построены на Alpine Linux и не зависят от пакетов ОС сервера: от ОС требуется только среда контейнеров |
| Клиентская часть | Веб-интерфейс в браузере на любой ОС рабочего места. Из браузеров в составе российских ОС: Яндекс Браузер и Chromium — на движке Chromium, на котором выполняются e2e-тесты интерфейса; Firefox — поддерживаемый браузер по ТЗ |
| Мобильные устройства | Отдельного приложения нет: интерфейс адаптирован для мобильных браузеров (ширина экрана от 360 px) |
