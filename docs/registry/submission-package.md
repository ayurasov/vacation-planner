# О документе

Документ — путеводитель по комплекту для включения программы «Планировщик отпусков» версии 1.0.0 в единый реестр российских программ для ЭВМ и баз данных (Правила утверждены постановлением Правительства РФ от 16.11.2015 № 1236). В нём:

- состав комплекта и назначение каждого документа;
- соответствие требований Правил документам комплекта и текущий статус;
- действия, которые должен выполнить правообладатель перед подачей;
- наблюдения, найденные при подготовке комплекта, с рекомендациями.

Требования Правил и форма заявления меняются; перед подачей сверьте этот чек-лист с действующей редакцией Правил, приказом Минцифры № 486 (классификатор) и инструкцией к личному кабинету на портале Госуслуг.

```bash

node scripts/third-party-notices.mjs        # уведомления и docs/sbom/sbom-components.csv — после каждого make sbom

make docs                                   # DOCX → docs/docx/, PDF → docs/pdf/ (python3 tools/docs/build_docs.py)
```

# Действия правообладателя перед подачей

## Юридические

1. Определить правообладателя и оформить права на весь код программы, включая результаты, полученные с ИИ-ассистентами, и общую с другими продуктами дизайн-систему (п. 1 таблицы).
2. Проверить условия использования ИИ-ассистентов, применявшихся при разработке: права на результаты должны принадлежать пользователю сервиса без ограничений на коммерческое распространение.
3. Утвердить лицензионный договор и публичную лицензию (`LICENSE.ru.txt`); добавить файл лицензии в репозиторий и дистрибутив, заменить `"license": "UNLICENSED"` в `server/package.json` и `web/package.json` ссылкой на него.
4. Подготовить учредительные документы и сведения о доле иностранного участия (для гражданина — документы о гражданстве).
5. При необходимости зарегистрировать программу в Роспатенте.

## Организационные

1. Заполнить поля `[заполняет правообладатель]` в документах 1, 4, 5, 6, 7 и пересобрать DOCX и PDF.
2. Утвердить модель лицензирования, прейскурант и условия поддержки.
3. Опубликовать на сайте: описание функциональных характеристик, руководства, стоимость, контакты.
4. Сделать основным репозиторий и CI на собственном сервере Gitea, а GitHub — зеркалом или закрыть его; держать базовые образы и пакеты npm в зеркалах организации (см. «Описание процессов жизненного цикла»).

## Технические

1. Отключить обращения сторонних инструментов в интернет (наблюдения 2–3) и проверить на стенде, что исходящих соединений за пределы стенда нет.
2. Обновить документы и руководства до редакции 1.0.0, внести выпуск 1.0.0 в `docs/versions.md` и `CHANGELOG.md` (наблюдения 5–6).
3. Добавить документы `docs/registry/` в сборку `tools/docs/build_docs.py` и собрать DOCX и PDF (наблюдение 11).
4. Сформировать SBOM на теге `v1.0.0`, перезапустить отчёт по лицензиям и `scripts/third-party-notices.mjs`.
5. Подготовить дистрибутив версии 1.0.0: архив исходных текстов, образы контейнеров с зафиксированными дайджестами, `SHA256SUMS`; включить в него документ «Сторонние компоненты и лицензии».
6. Развернуть демонстрационный стенд по «Инструкции для эксперта» из дистрибутива, сменить демо-пароли и выполнить все проверки.
7. Провести испытания совместимости с российскими ОС и оформить протоколы.
