# О документе

Оглавление регламентов эксплуатации «Планировщика отпусков» 1.0.0 (E52-04). Регламент — пошаговая процедура для администратора стенда: когда применять, что нужно перед началом, шаги с командами и ожидаемым результатом, проверка, откат и запись в журнал эксплуатации. Справочник по установке, переменным и командам — «Руководство по развёртыванию» (`docs/manuals/deployment-guide.md`); работа кадровой службы и администратора в интерфейсе — «Руководство администратора» (`docs/manuals/admin-guide.md`).

# Регламенты

| Регламент | Когда применять | Файл |
|---|---|---|
| Обновление версии | Вышла новая или исправляющая версия; переход с 0.6.0 на 1.0.0 (особые шаги); откат неудачного обновления | [update.md](update.md) |
| Резервное копирование и восстановление | Ежедневная проверка свежести копий; внеочередная копия перед рискованной операцией; база потеряна или испорчена; восстановление на момент времени; ежемесячная и ежеквартальная проверка восстановления | [backup-restore.md](backup-restore.md) |
| Переключение на реплику | Основной сервер PostgreSQL недоступен и не вернётся за 15 минут, реплика исправна; возврат к схеме с репликой после аварии | [failover.md](failover.md) |
| Действия по оповещениям | Сработало любое из 15 правил `deploy/monitoring/alerts.yml` | [alerts.md](alerts.md) |
| Диагностика замедлений и ошибок | Жалоба на медленную работу или ошибку с «Кодом запроса»; поиск причины по метрикам, журналам, `pg_stat_statements`, профилю процессора и снимку памяти | [diagnostics.md](diagnostics.md) |
| Разбор инцидента | Подозрение на подбор пароля, кражу сеанса (`refresh_reuse`), несанкционированное изменение данных; простой дольше 15 минут; потеря или искажение данных | [incident.md](incident.md) |
| Нагрузочный прогон | Ввод в эксплуатацию на новом оборудовании, расчёт мощности под численность организации, проверка исправлений производительности | [../performance/runbook.md](../performance/runbook.md) |

# Общие соглашения

- Команды выполняются на узле стенда из каталога, где лежат `docker-compose.yml` и `.env`: имя каталога задаёт имя проекта compose и имена томов (`<проект>_db-data` и др.).
- Переменная `C` — команда compose стенда: `C="docker compose"` или, на стенде с репликой и архивом WAL, `C="docker compose -f docker-compose.yml -f docker-compose.replica.yml"`. После переключения на реплику основной сервер — `postgres-replica`.
- Время в журналах контейнеров, в именах копий и в базе данных — UTC.
- Каждое применение регламента записывается в журнал эксплуатации организации; поля записи — в последнем разделе каждого регламента.
