# О документе

Заметки к выпуску «Планировщика отпусков» 1.1.0. Для кого: сотрудники и руководители, кадровая служба, администраторы стенда. Полный список изменений — `CHANGELOG.md`, порядок обновления — регламент `docs/runbooks/update.md` (раздел «Особые шаги 1.1.0»), решения — ADR-018.

# Коротко

- **Одна структура с «По Делу».** Подразделения — дерево с видами уровней, как в «По Делу»; структура и сотрудники переносятся между инструментами теми же файлами, что выгружает и загружает «По Делу».
- **Согласующий — по структуре.** Руководитель сотрудника определяется правилом «По Делу»: явный руководитель, иначе руководитель подразделения, а без него — первый руководитель выше по дереву. Перевод сотрудника и смена руководителя подразделения больше не требуют правки карточек.
- **Руководство в приложении.** Руководство пользователя открывается из меню, ищется и печатается; знак «?» у заголовка экрана ведёт к нужной главе.
- **Ревизия интерфейса.** Склонения счётчиков, праздники в заявке диапазоном, причина запрета импорта видна сразу.

# Что увидят сотрудники и руководители

- Пункт меню «Руководство пользователя»: оглавление, поиск по тексту, главы по ссылке, рисунки крупно, «Открыть PDF» и «Скачать PDF». Знак «?» у заголовка «Графика отпусков», «Моего отпуска», «Команды» и других экранов открывает главу об этом экране.
- Заявку согласует руководитель по структуре. Если в карточке руководитель не указан, это руководитель вашего подразделения, а если его нет — руководитель подразделения выше. Руководители вышестоящих подразделений тоже вправе решить по заявке — например, когда руководитель отдела в отпуске.
- Руководитель подразделения видит среди подчинённых всех сотрудников подразделения без явного руководителя — их заявки, карточки и график работы, а также руководителей вложенных подразделений, если над ними нет другого руководителя.
- Фильтр по подразделению в графике отпусков показывает его вместе с вложенными; численность в списке — тоже с вложенными. Подразделения в списках идут деревом с отступом.
- Мелкие исправления: «131 сотрудник», «4 заявки на согласовании» вместо «131 сотрудников»; праздники в заявке — «1–8 января», а не каждой датой; значок непрочитанных уведомлений не закрывает колокольчик.

# Что изменится для кадровой службы

- Справочники → «Подразделения»: дерево с видом уровня (компания, дирекция, служба, отдел, группа…), «+» в строке добавляет вложенное, в карточке — «Входит в», вид, руководитель, порядок и внешний ID. Одноимённые подразделения в разных ветках допустимы и различаются подписью «Отдел продаж — Север».
- Карточка сотрудника: «Первое лицо» (никому не подчиняется — заявки решает администратор), внешний ID, руководитель «По структуре».
- Новая страница «Импорт и экспорт»:
  - **Структура** — выгрузка и загрузка файла структуры «По Делу»; загрузка ничего не удаляет и не переименовывает, сначала показывает план;
  - **Сотрудники** — выгрузка CSV для Excel и JSON со столбцами «По Делу» и полями отпусков; загрузка с выбором по каждой коллизии (по умолчанию остаётся значение планировщика), одноразовые пароли новым сотрудникам;
  - **Быстрый импорт CSV** — выгрузка AD или кадровой системы «сотрудник → подразделение, руководитель», файл главнее;
  - **Остатки из Excel** — прежний импорт норм и переносов.
- Администратор задаёт глубину структуры и виды уровней в «Правилах организации → Структура компании».

# Что сделать администратору при обновлении

Подробно — `docs/runbooks/update.md`, раздел «Особые шаги 1.1.0».

| Изменение | Действие |
|---|---|
| Миграция схемы `20261101090000_org_structure` | Ничего сверх обычной копии перед обновлением; миграция только добавляет столбцы и индексы. Существующие отделы становятся подразделениями верхнего уровня |
| Подчинённые руководителя подразделения — по структуре | Предупредите руководителей: в «Подчинённых» и графике работы появятся сотрудники их подразделений без явного руководителя |
| Откат на 1.0.0 | Только восстановлением копии, сделанной перед обновлением: 1.0.0 не знает о вложенных подразделениях |
| `VP_VERSION=1.1.0` | Для установки из дистрибутива — в `.env` |

# Совместимость API

Только добавляющие изменения (контракт 1.1.0): новые операции `/org/*`, новые поля подразделения и сотрудника, правила организации `unitKinds` и `orgMaxDepth`. Поля `dept` и `deptName` содержат подпись подразделения — пока в организации нет одноимённых подразделений, это прежнее название. Путь `/departments/{ref}` принимает id или подпись.

# Безопасность

Закрыты две уязвимости зависимостей, отмеченные в 1.0.0: `deepmerge-ts` в утилите миграций Prisma и `uuid` в библиотеке выгрузок — `npm audit --omit=dev` не находит уязвимостей. Новые операции обмена доступны кадровой службе и администратору; настройки структуры из файла применяет только администратор; кадровая служба не меняет из файла учётные записи администраторов и коллег по службе. Выгрузки и загрузки фиксируются в журнале аудита; матрица прав дополнена пятью операциями.

# Известные ограничения

- У подразделения один руководитель: дополнительные руководители «По Делу» при загрузке не переносятся (план отмечает их «не переносится»).
- Функциональные руководители, часовой пояс и видимость «По Делу» в планировщике не хранятся: выгружаются пустыми и при загрузке пропускаются.
- Синхронизация структуры с Active Directory — в 1.2.0; до неё — выгрузка AD файлом через «Быстрый импорт CSV».
