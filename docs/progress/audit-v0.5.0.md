# Аудит функциональности и вёрстки v0.5.0

Полный аудит интерфейса и связанной с ним серверной логики перед выпуском v0.5.0: каждый экран прочитан в коде и пройден в браузере за четыре роли, вёрстка проверена автоматически на трёх ширинах и в двух темах.

**Итог:** найдено 18 функциональных дефектов и 6 групп дефектов вёрстки; все исправлены в v0.5.0, принятые ограничения — в разделе «Не исправлено». Серьёзные: правка карточки сотрудника округляла дробный перенос дней и не давала её сохранить; после сброса пароля или увольнения вкладка оставалась «вошедшей» и каждое действие заканчивалось ошибкой; при 5000 сотрудников руководитель не находил подчинённых вне первых 200; контраст текста в обеих темах местами 1,6–3,9:1 вместо 4,5:1.

# Вёрстка

Автоматические проверки по 216 страницам (4 роли × 9 экранов × 3 ширины × 2 темы) и 36 страницам телефона с сенсорным экраном. Замечание считается на каждом элементе каждой страницы.

| Проверка | До аудита | После | Телефон с сенсорным экраном |
|---|---|---|---|
| Горизонтальная прокрутка страницы | 0 | 0 | 0 |
| Элементы за краем экрана | 0 | 0 | 0 |
| Контраст текста ниже 4,5:1, светлая тема | 4 401 на 90 стр. | 0 | 0 |
| Контраст текста ниже 4,5:1, тёмная тема | 2 574 на 90 стр. | 0 | 0 |
| Обрезанный текст без многоточия | 64 на 8 стр. | 0 | 0 |
| Многоточие без подсказки с полным текстом | 244 на 32 стр. | 0 | 0 |
| Элементы управления без доступного имени | 0 | 0 | 0 |
| Цели нажатия меньше 24 × 24 px | 246 на 14 стр. | 0 | 0 |
| Ошибки консоли и неуспешные ответы API | 492 | 4 | 4 |

Цели нажатия до аудита мерились только на 360 px, после — на всех ширинах. Четыре оставшиеся ошибки консоли — по одной на роль на экране входа (раздел «Не исправлено»). Функциональные исправления проверены сценарием в браузере: 13 проверок из 13.

## Контраст

Дефекты контраста — в нескольких токенах, поэтому исправлены токенами: оттенки прежние, светлота — расчётом до 4,5:1 на каждом фоне, где цвет встречается.

В тёмной теме акценты светлее — так они читаются как текст на тёмном фоне, но под белой надписью дают 1,6–3,3:1: кнопка «Согласовать» — 2,27, синие кнопки и полосы графика — 3,30, счётчик заявок в меню — 1,64. Поэтому заливки под белым текстом и значками вынесены в отдельные токены `--color-*-fill`, общие для обеих тем; акценты остаются для текста.

| Токен | Было | Стало | Худший контраст до → после |
|---|---|---|---|
| `--color-text-soft` (подсказки, даты, подписи) | `#8a92a6` | `#646e84` | 2,75 → 4,52 |
| `--color-text-muted` (второстепенный текст, вкладки) | `#6b7280` | `#545b69` | 4,27 → 6,03 |
| `--color-primary` (кнопки, ссылки, полосы графика) | `#4f7cff` | `#3569ff` | 3,71 → 4,55 |
| `--color-success` (кнопка «Согласовать») | `#2fa96b` | `#258554` | 3,00 → 4,60 |
| `--color-danger` («Отклонить», праздники) | `#e5484d` | `#d01e23` | 3,47 → 4,50 |
| `--color-success-dark`, `--color-warning-dark`, `--color-violet` (метки) | `#1e8a52`, `#b56a10`, `#8e6fc1` | `#1a6d42`, `#a25f0e`, `#7c58b7` | 3,47–3,88 → 4,57–5,64 |
| Счётчик заявок в меню | белый на `#e8a13a` | белый на `#a25f0e` | 2,19 → 5,02 |
| Палитра аватаров (белые инициалы) | 8 цветов, до 2,19 | те же оттенки | → не ниже 4,50 |
| Тёмная тема: `--color-text-soft` | `#6f788b` | `#848c9d` | 3,47 → 4,55 |
| Тёмная тема: заливки кнопок, полос графика, отметки «сегодня», счётчиков | акценты `#5b87ff`, `#3cc282`, `#f26d71`, `#f2c27c` | `--color-primary-fill` `#3569ff`, `--color-success-fill` `#258554`, `--color-danger-fill` `#d01e23`, `--color-warning-fill` `#a25f0e`, `--color-violet-fill` `#7c58b7` | 1,64–3,30 → 4,55–5,40 |
| Тёмная тема: полосы «на согласовании» | `#e6aa4f` выбивался по светлоте из палитры | `--chart-pending` `#c2852a`, подпись `#2b1c04` | подпись 5,26–7,23 |

Палитра графиков после изменений проверена валидатором dataviz в обеих темах («согласован», «на согласовании», «по уходу за ребёнком»; месячная нагрузка): светлота, насыщенность, различимость при нарушениях цветового зрения и обычном зрении — в норме. Подписи на полосатых полосах «на согласовании» автоматическая проверка не меряет (фон — узор), они проверены расчётом по обеим полосам узора: 4,7–5,7:1 в светлой теме, 5,3–7,2:1 в тёмной.

# Не исправлено

| Что | Почему так |
|---|---|
| На экране входа — одна строка в консоли браузера: ответ `401` на `POST /auth/refresh` | Приложение при открытии проверяет, есть ли сеанс, запросом обновления токена: refresh-cookie недоступна сценариям (`HttpOnly`), другого способа узнать о ней нет. Без cookie ответ `401` — штатный, браузер лишь сообщает о нём |
| Янтарная полоса «на согласовании» в светлой теме — 2,19:1 к белому фону (для графики WCAG 1.4.11 просит 3:1) | Цвет — общий с оповещениями и меткой «на согласовании»; статус передаёт не только цвет: полоса заштрихована, на ней подпись с числом дней, есть легенда и подсказка |
| Руководитель и сотрудник при переходе на «Сотрудники», «Справочники», «Журнал аудита» попадают на график (36 страниц прогона) | Разграничение доступа: этих разделов нет в их меню |
| Экранный диктор проверен автоматически (имена элементов, имена окон по заголовку), но не вживую | Проверка с NVDA и VoiceOver — в приёмке v1.0.0 (E50-01) |

# Как повторить

Скрипты аудита (`layout.cjs`, `functional.cjs`) запускаются против `vite preview` и API на отдельной БД с демо-данными; они не входят в поставку. Регрессии закрыты тестами: `server/test/audit-fixes.e2e.test.ts`, `events.e2e` «отзыв сеанса закрывает уже открытый поток», e2e интерфейса «диалог заявки: имя, фокус, Esc; праздники через Новый год» и «сброс пароля: открытая вкладка сотрудника сама уходит на экран входа».
