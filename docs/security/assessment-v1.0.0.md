# О документе

Отчёт самооценки информационной безопасности «Планировщика отпусков» версии 1.0.0 для приёмки службой ИБ (история E50-02). В нём:

- автоматическая проверка матрицы прав — каждая операция API каждой ролью;
- найденные при самооценке недостатки и их исправление;
- самооценка по OWASP ASVS 4.0.3, уровень 1, с доказательствами;
- аудит зависимостей и принятые остаточные риски;
- пакет для внешнего теста на проникновение.

Самооценка не заменяет внешний тест на проникновение и не является сертификацией. Доказательство в отчёте — автоматический тест, который выполняется в CI на каждый push, или место в коде и конфигурации; ручных утверждений без ссылки нет. Сводный чек-лист из 16 требований для приёмки — документ 1, раздел «Чек-лист безопасности»; эксплуатационные меры организации — «Руководство по развёртыванию».

# Матрица прав

Тест `server/test/rights-matrix.e2e.test.ts` для каждой операции контракта вызывает её от имени каждой роли и сверяет ответ с ожидаемым:

| Ожидание | Что считается выполненным |
|---|---|
| Доступ | Ответ не `401`, не `403` и не `5xx`: права пройдены; `400`, `404` и `409` — проверки данных после прав |
| Запрет | Точно `403` (или `404`, где сервер не раскрывает существование чужого объекта) |
| Аноним | `401`, кроме открытых операций: вход, обновление токена, требования к паролю, настройки единого входа, производственный календарь |

Объекты, которые операция меняет (заявка, сотрудник, отдел, замещение), создаются для каждой роли заново — проверка одной роли не влияет на другую. Тест начинается с проверки полноты: каждый `operationId` контракта должен встречаться в матрице, и операция без строки в матрице роняет CI.

Дополнительно проверяется:

- карточка коллеги без служебной роли не содержит логина, почты, норм дней, табельного номера и служебных прав; полная — себе, руководителю, кадровой службе и администратору;
- поиск по табельному номеру доступен только служебным ролям;
- чужое уведомление нельзя пометить прочитанным;
- ранее существовавшие тесты прав по предметным областям: `staff.e2e`, `requests.e2e`, `delegation.e2e`, `notices.e2e`, `planning.e2e`, `security.e2e`.

Матрица прав для людей — документ 2, раздел «Матрица прав»; тест и документ сверены, расхождений нет.

# Найденные недостатки и исправления

| № | Недостаток | Важность | Исправление | Подтверждение |
|---|---|---|---|---|
| F-1 | В `docker-compose.yml` было значение `JWT_SECRET` по умолчанию, а сервер принимал access-токен без идентификатора сеанса: при запуске без `.env` любой, кто знает значение из репозитория, мог подписать токен любого сотрудника | высокая | Значения по умолчанию нет — compose не запускает стенд без секрета; токен принимается только с идентификатором живого сеанса из БД, поэтому одного секрета для подделки недостаточно | `auth.e2e` («токен без сеанса и с несуществующим сеансом — 401») |
| F-2 | PostgreSQL был опубликован на всех интерфейсах узла с паролем из репозитория | высокая | Порт опубликован только на `127.0.0.1` | `docker-compose.yml`; дымовой прогон CI |
| F-3 | Карточка и список сотрудников отдавали любому вошедшему нормы дней и перенос остатка коллег (баланс по матрице прав закрыт), табельные номера, логины и признаки служебных ролей | средняя | Коллеге без служебной роли — справочная карточка; поиск по табельному номеру — только служебным ролям | `rights-matrix.e2e` |
| F-4 | Обращения за пределы контура: проверка версии Prisma CLI при каждом старте (`checkpoint.prisma.io`), статистика установки пакета `@scarf/scarf` при сборке, проверка новой версии npm при старте через `npx`, значок проверки Swagger UI (`validator.swagger.io`) | средняя | `CHECKPOINT_DISABLE=1`, `SCARF_ANALYTICS=false` и `scarfSettings`, миграции без `npx`, `NPM_CONFIG_UPDATE_NOTIFIER=false`, `validatorUrl: null` | `server/Dockerfile`, `server/src/main.ts`; проверки независимости Н-1…Н-7 «Инструкции для эксперта» |
