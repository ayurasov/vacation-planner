# Промпты для разработки этапа 1 с ИИ-ассистентами

| Параметр | Значение |
|---|---|
| Документ | Промпты этапа 1 (документ 10 комплекта) |
| Версия | 1.0 |
| Дата | 27.10.2026 |
| Статус | На согласовании |
| Связанные документы | 6 — Правила с ИИ; 3 — Бэклог; `prompts/` |

## 1. Назначение

Готовые формулировки для ИИ-ассистентов по итерациям этапа 1. Промпт копируется целиком, ассистенту доступен репозиторий. Живые версии — в `prompts/base/` и `prompts/iterations/`.

## 2. Итерационная модель

Двухнедельные итерации I1–I4 поверх недель плана документа 3. Итерация = планирование (P01 на все истории) → цикл историй (P02–P09) → закрытие итерации (P12 + файл `docs/progress/iteration-N.md`). В одной сессии — одна история; длинный контекст — через `docs/progress/` (память ассистента), а не через повторное объяснение.

## 3. Базовые промпты (полные тексты в prompts/base/)

| ID | Промпт | Назначение |
|---|---|---|
| P01 | План истории | Разбор истории, вопросы, план работ |
| P02 | Тесты | Падающие тесты по критериям приёмки |
| P03 | Реализация | Минимальный код, проходящий тесты |
| P04 | Самопроверка | lint + test + contract, исправление |
| P05 | Фикс CI | Диагностика упавшего конвейера |
| P06 | Независимое ревью | Второй ассистент ищет дефекты |
| P07 | Критическое ревью | Человек: решения и безопасность |
| P08 | Документация | CHANGELOG, обновление docs |
| P09 | Закрытие истории | Чек-лист, метки, слияние |
| P10 | Закрытие итерации | Журнал итерации, ретроспектива |
| P11 | Разбор дефекта | Анализ причины, тест на регресс |
| P12 | Блокер | Остановка и эскалация человеку |

## 4. Скелет любого промпта истории

```text
Ты работаешь в репозитории vacation-planner по правилам AGENTS.md.
Задача: {ID}. {Название}.
Прочитай: docs/specs/03-backlog.md (эпик {E}), docs/specs/02-api-spec.md,
contracts/openapi-vacation-api-v1.yaml (operationId {…}), связные разделы docs/specs/01|04|05.
Критерии приёмки: {скопированы из бэклога}.
Порядок: P02 (тесты, красные) → P03 (реализация) → P04 (lint/test/contract зелёные).
Запрещено: менять contracts/ и docs/specs/, добавлять зависимости, трогать data.db.
Если контракт не покрывает задачу — остановись и задай вопрос (P12).
```

## 5. Итерация I1 — аутентификация и пользователи (недели 1–2)

Истории: E00-01…04, E01-01…06, E02-01…03. Промпт-вставка:

```text
Фокус итерации: безопасность входа. Изучи src/app.js и текущие таблицы в src/db.js.
Миграции оформляй файлами migrations/NNN-*.sql по docs/specs/04-data-model.md.
Пароли: scrypt (N=16384), верификация timingSafeEqual; секрет — process.env.JWT_SECRET,
в тестах — фиксированный тестовый секрет из окружения CI.
Каждая история — отдельная ветка story/<id> и PR по шаблону .github/pull_request_template.md.
```

## 6. Итерация I2 — заявки, балансы, аудит (недели 3–4)

Истории: E03-01…06, E04-01…03, E05-01…02. Вставка:

```text
Ядро — конечный автомат docs/specs/01-architecture.md раздел 8.
Сначала тест-таблица состояний: недопустимые переходы обязательны.
Все переходы проверяют права по docs/specs/02-api-spec.md раздел 8 и пишут
request_events + audit_events в одной транзакции.
Баланс считай в domain/balance как чистую функцию от заявок (без БД внутри).
Гонки тестируй параллельными вызовами fetch в одном тесте.
```

## 7. Итерация I3 — справочники, график, фронтенд (недели 5–6)

Истории: E06-01…03, E07-01…03, E08-01…04. Вставка:

```text
Фронтенд переноси из public/index.html в public/src/ по экранам; старый файл
живёт до E10-02 — не удаляй его и не правь без нужды; выносим код, а не переписываем.
API-клиент public/src/api/client.js — единственное место с fetch; ответы по контракту.
Все пользовательские строки в шаблоны через esc() — это критерий E08-04, тест на <img onerror> обязателен.
График: интервалы из GET /schedule, рендер диапазоном, не полным годом.
```

## 8. Итерация I4 — уведомления, миграция, приёмка (недели 7–8)

Истории: E09-01…02, E10-01…02, E11-01…04. Вставка:

```text
Миграция (E10-01): scripts/migrate-stage0.mjs работает на копии БД (DB_PATH во временный файл),
отчёт сверки печатается в stdout и пишется в docs/progress/migration-report.md.
Расхождение ≠ 0 — стоп и вопрос (P12).
Приёмка: прогони чек-лист docs/specs/08-tz.md раздел 14, каждое пункты подтверди ссылкой на тест/отчёт.
```

## 9. Признаки проблем в сессии

Ассистент: предлагает изменить контракт → останови (P12); тесты зелёные без новых тестов → проверь критерии; «попутно улучшил» → откатить лишнее; не находит файл из промпта → путь устарел, обнови промпт по репозиторию.
