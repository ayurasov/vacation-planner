| Версия | 1.0 |

| Статус | На согласовании |
| Связанные документы | 0 — Ревизия фич; 1 — Архитектура; 2 — Спецификация API; 6 — Правила с ИИ; 7 — CI/CD |

## 1. Назначение

Этап 1 (8 недель) раскладывается на эпики и истории. История — законченный объём работы, передаваемый разработчику или ИИ-ассистенту, проверяемый ревью за 30–60 минут. Бэклог переносится в трекер один к одному.

## 2. Правила бэклога

### 2.1. Обозначения

| Обозначение | Значение |
|---|---|
| `TL` | Технический лидер / архитектор |
| `BE` | Бэкенд-разработчик Node.js |
| `FE` | Фронтенд-разработчик |
| `QA` | Инженер по тестированию |
| `DO` | DevOps |
| Оц. | Идеальные человеко-дни с учётом генерации кода ИИ-ассистентом |
| Ревью ТЛ | `да` — обязательное ручное ревью технического лидера |
| Пр. | `M` — обязательно для этапа; `S` — желательно, переносится на этап 2 |

### 2.2. Готовность истории

Взята в работу, если: есть ссылка на раздел документа 1/2 и контракт; критерии приёмки проверяемы; зависимости закрыты или имеют заглушки; назначен ревьюер для историй с ревью ТЛ.

### 2.3. Закрытие истории

Закрыта, если: критерии выполнены и покрыты автотестами; CI зелёный (линтер, тесты, контракт); ревью пройдено; документация и CHANGELOG обновлены.

## 5. Ёмкость и загрузка

Суммарно ≈ 47 человеко-дней при ёмкости 8 недель × (1 BE + 1 FE + 0,5 QA/DO + 0,3 TL) ≈ 60 человеко-дней. Запас ~20 % на дефекты и ревью.

## 6. Критический путь

E00 → E01 → E02 → E03 → E04/E05 → E10 → E11. Фронтенд (E08) и справочники (E06) могут идти параллельно с балансами на заглушках контракта. Задержка E03 на неделю сдвигает выпуск — история с наибольшим риском, ревью ТЛ обязательно.

## 7. Перенос на этап 2 без ущерба

Кандидаты: E08-03 (polling → сразу SSE), E09-01 (только интерфейсные уведомления), E11-02 (нагрузка кратная, не полная). Недопустим перенос: E01, E02, E03, E05, E10 — без них этап 1 теряет смысл.
